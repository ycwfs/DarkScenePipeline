# 增强后去噪：实测结论

素材：`real-development-data/` 三段真实部署录像（大厅 / 报告厅 / 展厅1屏），
全部在**处理分辨率**（长边缩到 1280，超分之前）下测量。复现：

```bash
.venv/bin/python compare/results/denoise/denoise_probe.py \
  --video <输入暗源-xxx.mp4> --frames 10,30,50,70 --measure
```

## 1. 输入源本身噪声不算大

| 素材 | 尺寸 | 亮度 | 平坦区噪声 |
| --- | --- | --- | --- |
| 输入暗源-大厅 | 1920×1080 | 65.4 | 1.72 |
| 输入暗源-展厅1屏 | 1280×720 | 63.5 | 1.22 |
| 输入暗源-报告厅 | 2688×1520 | 71.2 | 1.08 |

亮度 63-71，**不是极暗**（ARID 最暗那段只有 2.1），所以增强增益仅约 2 倍。
干净图像该 <1，所以输入带噪但不严重；增强后升到 1.09-1.87，基本同倍放大。

**一个度量陷阱**：直接测交付的"输出亮源"文件反而噪声更低（两段测出 0.00）。那是因为
输出经过「缩到 1280 → 增强 → 超分 ×2」，双三次插值让相邻像素高度相关，逐像素指标必然
虚低。跨分辨率不能直接比，所以本目录所有数字都在超分之前测。

## 2. 去噪该放在增强之后，不是之前

三个场景趋势一致（下表为大厅）：

| 方案 | 降噪 | 边缘保留 |
| --- | --- | --- |
| 先去噪再增强 | 59-65% | 77-86% |
| **增强后去噪** | **73-75%** | **81-82%** |
| 两头都去噪 | 92-100% | 62-79% |

原因在数字里读得出来：暗帧信噪比太低，NLM 靠图块相似度判断，在暗图上这个判断本身不可靠；
而且**增强器自己已经承担了 64-76% 的去噪**（对照实验：同等提亮下比纯线性增益低这么多），
先去噪很大程度是重复劳动，剩下的照样被放大。等增强完画面结构清楚了再做，效果显著更好。

两头都做能到 92-100%，但成本翻倍、边缘掉到 62-79%，展厅那个 100% 其实是画面被抹平了。

## 3. 成本由搜索窗决定，不是滤波强度

| 方法 | 降噪 | 边缘 | 耗时/帧 (720p) |
| --- | --- | --- | --- |
| 双边 d5 | 35% | 84% | **5 ms** |
| 双边 d9 | 61% | 68% | 24 ms |
| NLM h3 窗7 | 51% | 85% | 119 ms |
| NLM h3 窗11 | 67% | 82% | 217 ms |
| NLM h3 窗15 | 75% | 81% | 376 ms |

看图（`real_大厅_denoise_zoom.png`，上排 2×、下排 5×）：窗15 数值最好，但视觉上已有
"塑料感"、地面纹理被抹掉，比 81% 这个数字显示的更明显。**窗7 是画质拐点**；
**双边 d5 性价比极高**（5 ms 拿 35%，ARID 上只有 10%，真实素材上好得多）。

## 4. 一并观察到的：真实素材整幅偏绿

见 `real_大厅_enhanced_full.png`。这正是之前"饱和度加倍导致发绿"的来源——底色本就偏绿。
现行实现围绕画面均值缩放已不会放大它，但**绿偏本身仍在**，消除它需要另加白平衡
（Shades-of-Gray 在 720p 约 52 ms）。
