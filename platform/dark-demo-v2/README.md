## 2026-11-02 低置信度候选复核

在最终动作阈值 `reco_min_conf=0.925` 之后增加可选的因果复核，默认开启，默认下限
`candidate_recheck_lower=0.85`。只有通过已有物体、挥手、跑动先验的候选才进入复核，
低分候选本身不会刷新高分锚点：

- **已确认动作续接**：同人物同一代次、同动作，距离最近高分锚点不超过1.2秒，且窗口相邻间隔不超过0.65秒。
- **跑动双窗口复核**：`chase` 候选需速度至少0.35人体框高/秒，并由两个相邻低分窗口覆盖至少0.5秒；确认后连续窗口可继续续报。

复核下限必须满足 `0.5 < candidate_recheck_lower < reco_min_conf`，且最终动作阈值必须大于0.5；
不满足时配置直接拒绝。复核恢复的事件保留原模型置信度，并进入绘制、事件日志和片段保存，
未通过复核的候选仍标为 `other`。固定的1.2/0.65/0.5秒和0.35速度值不作为平台参数暴露，
以保持平台与 NVIDIA-Box 行为一致。

## 2026-11-03 短动作显示与实时日志

逐人实时输出默认 `action_display_hold_sec=0.8`：刚确认的具名动作在下一异步窗口暂时变为
`other`或尚未返回结果时，画面最多继续显示0.8秒，并在标签末尾标记`*`。这是显示层的
短时保持，不会修改 `events`/`events.jsonl`、动作阈值或片段触发；要关闭可设为0，范围0–3秒。
因此短动作更容易在实时画面中看清，同时仍保留原有误报门槛。

逐人周期日志中的 `proc_fps` 是识别管线处理速率，不是 `/stream` 的输出节拍；输出节拍看
`max_stream_fps` 和 `[push]` 的 `adv/missed/ring_full`。`[selftest] 编码突发能力` 只测
JPEG 写入 ffmpeg 的短时上限，不能单独证明端到端出流不卡顿；需结合推流写阻塞、环形队列和
出流节拍一起判断。

`pose_overlay` 是骨架可视化开关，默认开启；关闭后实时画面和保存的动作片段都不绘制人物骨架，
但骨架模型仍照常参与识别与动作融合，不改变事件或片段判断。

## 2026-10-27 正式完整方案：挥手与跑动先验

用户已确认以压低误报为首要目标，正式启用 `wave_pose_min_frames=3`、`running_pose_min_speed=0.35`，设0可分别关闭。沿用原四参数0.972／35／0.925／0.581、正式七类物体检测器和原13份权重，不使用XCLIP或实验8/80类物体模型。

挥手：当前同人1秒窗口内，同一只腕高于双肩累计至少3个不同源帧，腕与双肩置信度均≥0.5；不强制连续。亮场姿态不足时拒绝挥手。跑动：共同可靠关节点约0.2秒间隔的平均位移速度除以人体框高，至少5关节、3对且覆盖0.3秒；阈值单位人体框高度/秒，不是像素/秒。低于阈值改其他，缺可靠速度时保留原结果。两项都在低亮、原图亮度未知或骨架关闭时跳过，不平滑、不增加模型前向或等待未来帧。

三类先验（物体、挥手、跑动）均在最终标签发布前执行，绘制、事件及按人/动作片段共用过滤结果。原模型概率保留，wave_prior/running_prior记录规则原因和证据；不能把规则分数解释为模型后验。几何条件仍可能被静止举手、骨架抖动或人体重叠满足，不能保证零误报。

平台更新代码包后须重新导入suanzi.json，旧任务显式参数不会自动变化。Box继承同一入口；多卡参数分配不变。交付名：dark-demo-v2_full_priors_20261027.tar.gz/.zip、NVIDIA-Box_full_priors_20261027.zip。模型来源与阈值见models.json；真实演示及最终归档实时验证记录在reports/full-prior-release-20261027，以下旧验证数字仅对应历史版本。原0.3.0镜像不增加依赖。

## 2026-10-27 物体检测框可视化

逐人结果默认同时显示人体框、启用的骨架和检出的物体框。物体用青色框，标签为人物ID、类别、检测置信度；bottle/cup/phone/camera/paper/item/exhibit分别为瓶/杯/手机/相机/纸/便携物/机器人或展品。动作被过滤为其他时，检出的非兼容物体也可显示。标签末尾“~”表示依据同一检测的局部光流短时跟随，不是该帧重新检测；分数仍为原检测分数。

检测帧带原图尺寸与采集时间。当前帧直接绘制；异步晚到结果需通过局部光流前后向一致性校验，最长显示至检测后0.6秒，无法对齐/断流/人物代次不符/当前原L<35时隐藏。新的空检测清除旧框。显示缓存每路最多64帧/24MiB/0.6秒，不保存无界历史。流式输出与动作片段共用绘制规则；离线完整视频缓冲1.2秒/最多64帧，保存侧沿用1.2秒事件缓冲，将晚到的物体结果画回原采集帧。实时输出不增加此缓冲，因此两者出现物体框的时刻和持续时间可能不同。动作类别仍按原事件时间显示，不提前。物体事件缓存最多256条/2.5秒。

此为可视化更新，六个主模型及13份权重不变；alpha=.972、门35、动作.925、物体.581不变。仍只对通过动作阈值的喝水/捡物窗口按需检测物体，并非每帧全画面物体检测，所以没有物体框不等于现场没有物品。不开启额外GPU检测，也不把跟随结果用于动作判断。原0.3.0镜像无需重建或重传。

# 暗光逐人动作识别算子 · 20261026

视频／实时流 → 原图亮度 → 增强 → 人体框与跟踪 → 每人的 RGB ROI 和骨架动作 → 同人融合 → 动作阈值 → 喝水／捡物的同人物体先验 → 逐人显示、推流与片段保存。无全画面动作底栏，不做骨架平滑。

## 物体先验

使用独立现场七类 YOLO26m，**不是人体检测权重，也不是旧 COCO max_prior 模型**。仅对动作阈值通过后的喝水／捡物候选按需推理，物体模型和 RGB/ST-GCN 位于同一动作工作进程；不对每个人每一帧都跑物体检测。

每个人 32 帧窗取位置 0、8、16、23、31，重复源帧去重。在原图坐标上将该帧人体框外扩 30%，另取可信姿态的头／手／腿局部区域，映射到增强后的 720 图裁剪，再做 640 letterbox 物体检测。使用实时缓存的准确人物轨迹和同帧姿态；人体框与别人 IoU>0.4 时该观测视为绑定不确定，不用别人的证据支持当前人物。

- 喝水：至少一个采样帧在同人 ROI 内检出瓶／杯且置信度≥0.581。
- 捡物：至少一个采样帧检出瓶／杯／手机／相机／纸／便携物且置信度≥0.581。
- 窗口及采样帧原 L 均需达到照度门；低亮、默认门下原 L 未知、全无有效观测时不否决。
- 有可用的亮场观测，但所有采样帧均无兼容物体时，最终改为 other。其他动作不经此过滤。

不要求物体连续全程可见。检测到周围物体也不证明真实交互，相机仍可能误认瓶，遮挡／小物体漏检仍可能误杀真实动作。这里未引入手机／相机／展品否决规则。启用先验后模型加载或推理失败明确上报，不能静默关闭模型后继续声称先验有效；“观测不可用弃权”仅指图像／人物绑定证据不足。

增强帧历史按时间 1.2 秒、120 帧和 128 MiB 三重限界，任务仅携带 5 个采样帧引用；检测结果 LRU 限 512 个裁剪，动作邮箱保持有界／实时同人任务合并。不会随无限流保存全量增强帧。非默认超大处理尺寸可能使证据缓存提前淘汰，记录中会显示观测不可用。

## 保存与稳定性

按人物 ID＋动作独立保存完整画面，文件名含 E/T/G/R 编号；多人同时动作允许片段重叠。直播不等待保存；保存侧缓冲 1.2 秒对齐异步事件并重绘最终类别。前后各 2 秒相对识别触发及最后同类事件，不是已知真实动作起止保证；长动作 15 秒重叠续段。断流、缓存不足、漏识、过载、强杀可能造成上下文不足，同名 JSON 的 context_complete 记录覆盖情况。

本地临时编码完成后交付 clip_dir（可挂 NFS）；收尾消息不丢弃，真实写盘错误明确失败，拥塞掉帧／弃段有计数。上传失败保留本地并告警；离线交付失败非零退出。流打开／读取超时 3/2 秒，断流重连，每种推流由 FFmpeg 独立恢复。本轮验证记录见 `reports/person-object-release-20261026/`；有限回环验证不保证无限时长零故障。
