# Box单卡优化协议（2026-10-28）

范围：仅NVIDIA-Box及其打包工具；平台源码、正式平台归档、镜像和原训练权重保持。
目标设备用户确认Orin Nano 4GB Super、ARM64、34TOPS、共享4GB内存；JetPack版本和SSH未提供。
开发机全部实验每进程只暴露一张RTX3090，不把其他GPU实验合算为单卡性能，也不模拟Orin真机。

正式策略固定：720输入、alpha .972、照度门35、动作.925、物体.581、挥手3真实源帧、
跑动.35框高/秒、前后2秒、按人/动作独立全帧片段。禁止把减少触发量直接当作误报降低。
本轮不改训练集或阈值，不替换未适配现场的小模型。性能候选执行原模型，评估数值/跟踪/标签变化。

1. 冻结原Box runtime，先对暗/临界亮度/真喝水/儿童多人/密集相机场景各最多150原帧剖析。
2. 单模型CUDA Graph、layout、torch.compile、ONNX FP16作为微测；不能把单模型加速当全链收益。
3. 复用历史固定23输入清单，覆盖亮度7–154及最多19个人体候选。旧样本已经使用过，不叫独立泛化测试。
4. 原版与候选真实300秒25FPS RTSP→RTMP，外部FFmpeg持续录制、HTTP三格式观看者重连、
   SIGTERM排空。原版1440输出，目标低内存候选720输出，必须明确显示差异；模型输入同为720。
5. 处理FPS只数实际消费的源帧，15FPS编码上限不作模型FPS。报告丢旧源帧、动作窗口合并、
   决策年龄、输出间隔、存储错误、上下文完整性。延迟起于OpenCV交付解码帧，不包含摄像机/网络缓存。
6. 数值检查采用相同源帧。实时调度会改变采样/轨迹/事件，不拿不同相位事件数作准确率。
7. 原图/增强像素、FP16检测及最终动作均核查；明显改变增强效果或新增已知误报的候选不得无说明晋升。
8. RTX独立显存和主机RSS分别报告，不能直接相加或声称等效Jetson统一内存。4GB适配需要板端实测。

尝试记录：最初CUDA Graph在整链发现autocast临时权重地址生命周期错误，保留失败日志；
修复缓存捕获后5样本197窗标签一致，但图池增加内存，因此4GB默认关闭。FP16 ORT小模型
微测提升有限且ARM64依赖受限，改为评估JetPack TensorRT。增强TensorRT128MiB工作区不足，
按构建错误提高为192MiB；不是屏蔽模型失败。后续以实际输出和稳定性决定是否交付该后端。

最终冻结：人体/物体TRT FP16、姿态TRT FP32（TF32关闭），原PyTorch增强、128帧uint8缓存、batch2、Graph关闭、720直接输出。增强TRT像素偏差候选否决；torch.compile未采用。最终代码来自独立解包review归档，最终发布仅补文档和报告数字并核对执行文件/权重字节一致。

主流300秒单GPU0结束后，顺序运行六模型自检、实际run.py入口、23样本、原5样本等长150帧探针、110秒故障恢复。无并行GPU负载用于性能汇总。全部命令和环境见final-suite.py/final-suite.json；真实流包装器只记录元数据，不修改像素。生成299.933秒展示版仅裁外部录制两端连续黑画面，不重做模型推理。
