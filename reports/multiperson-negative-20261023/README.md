## 如何读画面

- 每个有效候选旁的文字是**自己的骨架分类与原始类别概率**，包括其他；并未强行改成用户预期的other。
- 黄色骨架及 `*` 表示该窗口分类概率最高的候选；绿色为其余候选。将所选候选的完整10类向量与RGB按 `0.7×RGB + 0.3×骨架` 融合，最终底栏再应用0.75拒识阈值。
- 0.75作用于底栏最终判定，没有另外把低分人物标签隐藏。因此人物边上可能出现“喝水39%”等，底栏仍为其他。
- 每段开头约1秒是窗口积累期，不显示骨架；后续沿用生产代码的光流跟随。每段是独立切片，未跨视频接续历史窗口。
- 多人同框并不意味着全覆盖：本批抽样检出9～15个姿态候选，而现役识别上限仍为6。排序、遮挡和末帧质量筛选会影响入选者；槽位不是跨窗口身份ID。

## 实际暴露的问题与口径

**底栏20/20为其他，不代表逐人动作或人体检测全部正确。** 120条候选骨架分类中98条other、22条具名动作（喝水10、捡拾5、挥手3、握手2、投掷1、追逐1）。这是逐事件预测构成，不能作为独立人数或人员动作准确率。

人形机器人和机器狗会被RTMO误检成COCO人体骨架；0060截图左侧人形机器人有骨架，0054截图中的机器狗也有骨架。它们会占用最多6人的候选名额，也可能参与后续分类与最高分选择。已按模型原样显示，没有手动删除。其他被遮挡、边缘或未入选的真人可能没有标注。

这些源视频已由旧线上算子增强、超分、去噪并带旧标签条。本次裁掉底部76像素旧条（1680×1020→1680×944），再缩至720×404供识别，绘制仍用1680×944原内容并追加新条；**不重复增强、超分或去噪**。没有原始暗光帧，`raw_frame=None`，按现役代码原图不可用时的策略跳过照度判断、运行骨架分支。配置默认门75未改变，但这批回放不能证明原始视频在门75下是否激活骨架，也不是原始摄像头全链路回放。

P套件曾用于pn模型训练，pn2继承该训练线；本次又按多人场景筛选了6段，因此不能把本次零视频级触发当成新数据泛化、全部96段无误报或线上零误报证明。没有重新训练、修改阈值或更改生产代码与交付包。

## 文件与复现

- `selection.json`：六段源文件与挑选原因；`candidates.json`：96段抽帧姿态候选统计，候选数不是真人标注数。
- `sample-results.json` / `summary.json`：逐视频统计与合计。
- `events/*.json`：逐事件全精度RGB/人物概率、有效候选、最终结果与选中标记；`*_frames.json`：逐帧显示数量。
- `media-verification.json`：逐视频H.264、尺寸、帧率、完整解码校验。
- `source-verification.json`：与10-22交付包的文件哈希一致性记录。
