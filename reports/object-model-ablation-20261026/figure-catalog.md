# 图表说明

## 03-false-positive-tradeoff.png / .pdf（用户确认后新增）

目的：同时展示先验减少误报的收益和新增漏报的代价，补足前次只突出漏检的解读。左图绿色为从526误报窗中正确过滤的数量、棕色为仍保留的误报；右图显示同一设置对唯一用户确认真喝水的保留/误过滤。固定动作0.85、物体0.35、照度门30，使用原预测，无重训。

来源：false-positive-tradeoff.csv，全9段触发范围已由用户明确确认。横轴为计数，无误差棒；相同人数/时段重复窗口不能当独立试验。应注意n/s误报压制98%以上是实在收益，但所有设置也误过滤1个真喝水。微调m高清比720增强留下更多误报；不能只看旧正样本召回宣布高清全面更好。

该图把下一步的判断标准改为同时控制假警报和保留真实动作。单个正例不足以估计总体召回，分母仅包含原模型已触发窗口；不会由此判断未触发时段或捡物准确率。另提供候选分组计数减少重复窗影响，但不是实际输出片段数。

## 04-pickup-tradeoff.png / .pdf

目的：并排给出新37个捡物候选的先验过滤量、旧test真实捡物保留/漏报、旧test已知误报的过滤/残留。左图新触发没有逐窗GT，按用户“基本全误报”的总体审核意见背景统计，因此只是候选抑制；中右图使用旧test的既有标签，分别有4个正例和3个误报。无误差棒。

应注意高清微调m保留4/4真捡物并过滤1/3旧误报，720增强保留3/4、过滤2/3；n/s虽然过滤全部3个旧误报，但把4个真例也全过滤。新37窗高清n/s过滤35/37、36/37；微调m720增强过滤37/37，无法据此独立判断谁更准确。结合保留窗口逐帧预览可见单帧检测到附近瓶/纸/手机，可能使原捡物误报继续放行。图不能被解释为真实视频准确率或模型泛化成绩。

## 01-object-recall.png / .pdf

目的：比较相同旧test审核区域上，四模型×四输入是否真正检到了瓶和手机。横轴模型，颜色是输入方式，纵轴IoU≥0.5的GT匹配数，柱上注明检对/GT；不是mAP、没有误差棒。数据来自object-counts.csv，47图、瓶12/手机3框；原始41图子集的这两类检对数一致。

应注意：公开n/s/m均为0；微调m高清瓶4/12，720两种输入3/12，手机均0/3。该图支持“换小公开模型未解决当前漏检”，不能证明模型普遍无检测能力。FP另见CSV，不可只比较召回；相机和杯无GT无法下结论。召回差的不确定性见统计附录，0值也不表示等效。

建议图注：固定640/FP32/one-to-one、conf0.35/IoU0.5；辅助审核小样本、同场景；m_finetuned的现场训练与公开模型不同，属于方案对比而非纯架构消融。

## 02-feedback-support.png / .pdf

目的：展示输入/模型如何影响新9段的物体支持覆盖。横轴模型，颜色是输入，纵轴有单帧物体支持的动作窗数，左右分别喝水/捡物。数据来自feedback-counts.csv，527喝水候选/37捡物候选；无误差棒。

应注意：微调m高清支持更多喝水，但其中包含相机假瓶；更多支持不等于更准确，较少支持也不等于纠正误报。1个喝水窗口因绑定不可用而保留，未混入支持数。公开模型捡物只有共同三类可支持，不能直接解释为同类别完整能力的比较。

该图提醒下一步必须补充动作/物体真值和相机反例，不能按“保留最少”选优。图注必须写明新录像无完整动作GT以及不同模型的类别覆盖。

## examples/*.jpg（8个固定实例）

目的：展示同一源帧同一人物周围ROI，四模型×四输入的实际预测；每格标明模型、输入方式和裁剪原始像素尺寸。列顺序n/s/m/现场微调m，行顺序高清原图/高清gamma/720原图/720增强。置信阈值0.35；仅画公开模型共同物体类，微调模型画七类。

数据与选择：沿用前轮demo-plan中的8个事件，固定选择有效采样列表中间帧、全人ROI，不根据本轮分数挑帧。HTML中另给完整窗口决策表，因此单帧没框但整窗获支持并不矛盾。

关键观察：new09-supported显示手持相机被微调m标为瓶，高清也未消除；new05-phone显示公开m在增强ROI将手机区域判cup，高清没有此框；old-drink-supported中公开模型漏瓶而微调模型命中。局部ROI可能包含邻人，必须查看人物关联和其他采样帧，不能把图上任意框等同于该人的交互证据。

解读限制：这些是代表性反例说明，不是8个独立泛化测试；静态图不能证明动作完成，模型输出不是人工标注。全部样本及决策见inputs/action-results，预设帧清单见examples.json。
