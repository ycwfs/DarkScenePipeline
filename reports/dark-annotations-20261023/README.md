|---|---|

| 按文件内容去重 | 413 段：原清单 407 段 MP4，加上原先漏列的 6 段 AVI |

| 当前人体框草稿 | 16,960 个；4,994 帧无框，含空景及无法定位的人影 |
| 当前骨架草稿 | 14,670 帧至少有一个候选关节点，5,222 帧无可绘制关节点；不代表这些骨架均正确或完整 |
| 排除的处理后数据 | 两批线上回传共 128 段；已增强视频无法还原原图照度，因此不当成真实原始暗场 |
| 人工审核状态 | 原有两张示例仅人体框获用户确认；新框、骨架、插值仍待用户核对 |

四个目录是 `real-actiondata-all/`、`real-actiondata-0909/`、`real-actiondata/`、`real-actiondata-cutdrink/`。本次沿用用户确认的“现场数据”范围，不扩入 HMDB/Kinetics/ARID/dark-48 等通用视频。

亮度完全按运行时定义：原始未增强帧先按最长边 720 等比缩小、宽高取偶数，再计算整帧 `L = 0.114 B + 0.587 G + 0.299 R`。本轮以**单帧**严格 `<75` 筛选；运行时动作识别的窗口平均门与它不完全相同。L 是 0–255 图像平均亮度，**不是 lux**，且保留画面中的黑边、暗屏区域；符合阈值不等于人物局部一定很暗。

原 407 段的全帧 L 与历史缓存逐帧差异为 0。三个 AVI 的容器帧数含空缺块，与实际可解码帧数不一致；已用 ffprobe 和 OpenCV 双重解码核对，以真实解码帧编号、源 PTS 保存记录。对照 MP4 用名义恒定帧率编码，AVI 原始时间戳显示在底栏；其空缺时间不被伪造成额外图像。

## 标注从哪里来、哪些还不确定

1. 每个暗帧在原图、Gamma（0.45）、Retinexformer 视图运行 YOLO26m 和 RTMO-s，合并人体候选；再用 RTMPose-s 对人体区域补姿态候选。也保留上一轮增强图检测的候选框。此处为了离线标注主动运行姿态，**不受运行时 L<75 关闭骨架分支的门限制**。
2. 坐标统一映射回原图。框、骨架来源、模型分数、模型分歧和低可见性提示均保留。模型置信度不能当作 COCO 的真实可见性；审核前 `keypoint_visibility` 为 `null`，训练开关始终为 `false`。
3. Codex 对全部 167 个来源的中间暗帧总览做了目视检查，并对 10 段漏检明显的视频进一步查看六帧序列、补了 **60 个视觉人体框锚点**，其间 **749 帧**线性插值明确标为未逐帧核实。这些插值可能在突然转身、弯腰、加速时偏移，不能直接当精确真值。
4. 原示例另有 10 个视觉框锚点（此前 6 个＋本轮首尾 4 个），两帧获用户确认的是 `捡东西1/F000032`、`挥手18/F000030`。仅保留这两帧的框确认状态，不扩大解释为整段或骨架已确认。
5. 对 `挥手18/F000030` 的可见身体补了 12 个视觉关节点草稿，面部点没有猜测；`捡东西1/F000032` 虽然能定人体框，弯腰遮挡下的骨架仍不能可靠定位。视觉关节点也需要用户确认，其占位分数 0 不代表模型置信度。
6. 在实际查看的关键帧上去除了 **16 个椅子、屏幕、地面小物体误框**。同视频其他帧的相似框只标疑点、不自动整段删除；证据保留在 `visual-rejections*.json` 和逐帧 `assistant_rejected_proposals`。

**全量覆盖的是审核集合，并非每一帧都已有可靠完整骨架。** 无框帧既包含空景，也包含未能定位的人影；有框帧也可能漏第二个人或包含误检。未画出的关节点可能是低置信度、遮挡、出画或未知，不能自动补成合理姿势。最终无框帧和候选框计数见 `summary.json`，均不是检测召回率或准确率。

`喝水8` 的极暗竖幅区域、`挥手11` 等屏幕幻影人、`捡东西6` 的遮挡人物，以及其他弯腰/高速运动片段应优先核对。人物 ID 只是草稿的短期关联号，`P900` 表示本轮补的视觉锚点轨迹，不代表家庭身份，也不保证跨片段或遮挡后的 ID 一致。

## 怎么反馈

可以直接告诉我：**文件名＋原始帧号/时间＋人物编号＋问题**，例如：

> `挥手18.mp4，F000030，P001：右手腕位置不对；身体框正确。`

也可在页面直接操作：

- 框模式下拖动角点改边界、框内拖动移动；漏人用“添加人物框”。删除背景误检后再核对剩余人物。
- 骨架模式下选择点名并点击补点，或拖动已有点。左右以人物自身为准；可见用 v=2，遮挡但确能定位用 v=1，无法定位用 v=0。
- “本帧所有人体框正确”表示已检查整帧、没有漏标人物；“框＋显示的骨架点正确”还会将绘制的候选点确认为可见，未定位点为 v=0。请先改掉错误点和遮挡点。
- 看不清就标“看不清 / 排除”。只有核对原图与上下文确实无人，才点击“确认无人”。
- 添加问题备注后点“导出审核 JSON”。修改会暂存到当前浏览器，**不是已经写回仓库**；大量修改可能超过浏览器暂存配额，请定期导出。导出的 JSON 可再次导入继续审核。

浏览器测试生成的 `evidence/synthetic-browser-feedback.json` 是**测试数据**，不是真实人工确认，不得作为训练标注。

## 审核后的微调顺序

先用通过审核的完整人体框微调当前 YOLO26m 检测器，优先解决暗衣服、弯腰和遮挡漏框，同时加入人工明确确认的椅子/展台等空景负例。训练输入要兼顾实际运行时的增强后 720 画面，原图可作受控增强对照。Retinexformer 本轮固定，不重新训练。

只有关键点和可见性核对完成的样本才能用于姿态微调；RTMO-s 是当前运行时模型，RTMPose-s 在这里仅作辅助标注器，不能把换模型后的指标冒充 RTMO 微调提升。不将模型自己预测出的未知/遮挡关节点当成真值。

沿用已有源视频家族/会话分组及 train/val/test，原片和裁片不能跨集合。新发现的 AVI 暂为 `unassigned`，须核对其与旧裁片的来源关系后再分组。即使用户确认了 test 标注，也只用于最终评估。报告人体检测召回/误报、姿态关键点质量、逐人动作输入覆盖和最终动作结果，并补亮场回归与实时速度检查；不能只报告有框样本的动作准确率。

审核 JSON 先用以下命令做结构和来源验证，**这条命令不会训练或写入训练集**：

```bash
.venv/bin/python reports/dark-annotations-20261023/scripts/check_feedback.py 审核反馈.json
```

## 复现与证据

运行环境沿用仓库 `.venv`。执行顺序：`scan.py` → `run_proposals.sh` → `refine_visual_anchors.py` → `apply_visual_rejections.py` → `apply_pose_anchor.py` → `build_review.py` → `verify_dataset.py`。GPU 脚本先查空闲卡；本次使用物理 GPU 2–5，未占用其他任务所在的 0、1 卡。

| 用途 | 模型 |
|---|---|
| 人体候选 | `yolo26m_detect.onnx`，COCO person |
| 整图人体与骨架候选 | `rtmo-s_end2end.onnx`，COCO17 |
| 给定框的姿态候选 | RTMPose-s / SimCC / body7，256×192 |
| 提亮辅助视图 | Retinexformer `NTIRE.pth` |

四份权重的路径和 SHA256 见 `models-shard-*.json`。`evidence/browser-check.json` 记录真实 Chromium 的坐标拖拽、可见性编辑、导入导出、刷新暂存、三视图和窄屏检查；`verification.json` 记录覆盖、标注结构及对照视频解码校验。
