## 数据口径

- **流程图**：当前代码，处理长边默认 720；没有把测试历史参数写成当前默认。
- **图 03、05、06**：同一次历史 pn/840 记录，原始文件和当时照度门扫描结果已复制进
  `sources/` 并保存 SHA256。没有混入旧权重 177 个触发的结果，也没有拿本轮单帧诊断当作
  动作模型的新评测。历史记录含四位舍入字段和旧工具无人策略差异，不能作为现代码精确回放
  或 720 新包验收；严格复验需要修复后的 schema_version=2 导出。
- **样本关系**：P 的 460 窗口来自 96 段平台回传片段，pn 加训使用了这批数据；C 的
  18 窗口来自 4 段现场正样本，也属于训练内。窗口包含全片与重叠滑窗，不是 460/18 个独立
  视频；P 有少量标注歧义。因此图中称“负样本触发”，不把这组比例当作独立泛化误报率。
- **图 04**：对既有审查保存的 840×472 JPEG，用当前包的 YOLO26m 权重和前后处理，在
  CPU 上运行一次诊断。输入 640、检测阈值 0.25。四张原图/增强图均只检出人；该结果不能
  推广为所有正常亮度场景都漏检。蓝框是真实模型检测框，橙虚线仅为人工观察区。
- **图 05 例子**：P0029/t0.5，RGB other=0.8403，三部曲骨架候选 chase=0.904451，
  alpha 的 chase=0.248。两模式骨架汇总方式不同，不能把该候选分数直接代入融合公式
  复算 alpha 分数；图中数字均读取原记录。

建议讲解顺序：先用图 01、02 讲方案差别，再用图 03 讲现象，图 04、05 讲两条失效路径，
最后用图 06 说明照度门解决的是暗场旁路问题。详细讲稿见 `讲解备注.md`。

## 复现

在仓库根目录，使用已有 `.venv`。会议工具依赖安装在本目录 `.tools/`，未改镜像或项目依赖：

```bash
uv pip install --python .venv/bin/python --target reports/meeting-20261015/.tools \
  --no-deps python-pptx lxml XlsxWriter
.venv/bin/python reports/meeting-20261015/scripts/probe_objects.py
.venv/bin/python reports/meeting-20261015/scripts/build_assets.py
```

只重新生成原生可编辑 PPT，无需重新运行模型或生成静态图：

```bash
.venv/bin/python reports/meeting-20261015/scripts/build_editable_pptx.py
```

静态数据图使用 Matplotlib，原生 PPT 使用 python-pptx；pubfig 的依赖下载未完成，未用于本次产物。
构建脚本从源记录计算图表值，同时导出 CSV、JSON、PNG/SVG/PDF、draw.io 和原生 PPTX。
`evidence/` 保存检测框、图表数据和验证结果。构建脚本会同步仓库中的流程图文件。
`evidence/editable-qa.json` 记录原生对象、内嵌工作表、编辑后保存重开和 PDF 渲染检查。
