# 逐人 RGB 与骨架动作融合演示（2026-10-23）

已实现独立演示：检测人体、短期跟踪、按人裁剪视频序列、同一人的骨架分类、逐人alpha融合，框下显示该人的最终类别。**不再运行整幅画面的RGB动作预测，不再输出全画面动作底栏，也不再从多人中只选一个人的骨架。**

根据用户确认，本轮只做演示，平台及NVIDIA Box生产包没有切换。参数保留alpha=0.7、最终阈值0.75、原图照度门75。

先看 [全部7段预览](index.html)、[指定多人0060](videos/多人0060_逐人融合.mp4)、[双人挥手3](videos/挥手3_逐人融合.mp4)、[喝水16](videos/喝水16_逐人融合.mp4)。预览页可慢放，并能展开查看每条轨迹实际送进VideoMamba的裁剪图。`逐人动作融合演示_20261023.zip`包含视频、截图、输入裁剪、记录和代码。

## 已实现的算法

```text
原视频 → 缩至长边720 → Retinexformer增强
                        ↓
            YOLO26m人体检测 + 短期跟踪T01/T02/…
                        ↓ 每条轨迹分别积累约1秒
            ┌─────────────────┴─────────────────┐
         此人的视频裁剪                       此人的骨架序列
       VideoMamba pn2 / 32帧                 ST-GCN / 同32个时刻
            └─────────────────┬─────────────────┘
                  此人的0.7×RGB + 0.3×骨架
                              ↓ 阈值0.75
                   人体框下显示此人的类别与分数
```

模型仍为现有YOLO26m COCO-80检测头、VideoMamba-Tiny pn2、RTMO-s COCO-17姿态、ST-GCN和Retinexformer，权重未改。该流程使用人体检测类别0，不调用三部曲的物体先验否决。

- **框与跟踪**：检测阈值0.35，重复框NMS 0.75；每帧检测，结合位置、运动预测、衣着颜色直方图与可用骨架做一对一匹配。本轮没有旧版6人上限，不遗漏处理已经通过筛选的检测候选。检测器没有检出的真人仍然不能分类。
- **人物输入**：围绕该帧该人的检测框外扩15%，截取矩形ROI；等比例缩放、灰色填边成400×224，按pn2的均值/标准差归一化。每条轨迹有独立历史。不是实例分割，人与人遮挡重叠时ROI仍可能包含旁人；也不是把原全画面结果复制给所有人。
- **时序**：每条轨迹约1秒窗口，按同一组时间戳取32帧RGB与骨架；最多每0.5秒更新一次动作。新轨迹显示“识别中”，历史不足不强行给类别。间断超过0.2秒清空动作历史，轨迹丢失超过0.4秒新建ID；消失的人不继续画旧框，结果超过1秒不继续展示。
- **同人骨架**：每帧RTMO整图推理一次，将骨架一对一分配给检测框，再保存到对应轨迹；窗口重用已存姿态，不重复推理旧帧。ST-GCN独立分类各轨迹，沿用COCO-17归一化；至少一半采样帧有10个可见关节，末帧也需满足质量要求才参与融合。
- **照度门**：使用增强前整图平均亮度，窗口平均值低于75时，该人的结果只取自身RGB。为避免门下无用姿态计算，单帧在门下时不运行RTMO。画面无原始亮度时按既有不可用策略跳过亮度判断。
- **姿态不可用**：沿用既有soft策略，`0.7×该人RGB + 0.3×other单点分布`，日志记为`rgb_soft_no_pose`；不会借用另一个人的骨架。低亮度门触发时直接RGB，不加此soft项。
- **呈现**：绿框为其他、橙框为具名动作、灰框为识别中。具名动作的最终概率低于设定阈值（默认0.75）时统一显示“其他”，不显示低分动作名；所有“其他”标签只显示文字，不附百分比。达到阈值的动作才显示名称及概率，比较使用未舍入概率。绘制层也检查事件携带的阈值，旧事件缺少阈值时使用0.75。框下文字是该人的最终结果，双分支有效时同时显示细骨架。密集标签错位放在框下附近并用线连接；贴住画面下边缘的框将标签移入可见区。T编号只是短期轨迹编号，不是家庭身份。

代码：[person_core.py](scripts/person_core.py)、[demo.py](scripts/demo.py)。RGB全场共享一份网络，以每批2个人推理，避免每人重复加载模型。批次中的每个输出独立融合，没有多人平均或最高分筛选。

开发机已有原生Python3.10环境、RTX3090物理GPU2，7段完整视频，共696帧、233次**逐人判断**。以下数目是预测事件构成，不能把233当独立样本数或人数。

|---|---:|---:|---|---|
| 挥手3 | 3 | 22 | 挥手10、喝水11、其他1 | 原图在门下，逐人RGB |
| 挥手4 | 2 | 24 | 挥手12、喝水7、其他5 | 原图在门下，逐人RGB |

| 多人0055 | 16 | 101 | 其他101 | 双分支75、姿态不可用soft 26 |

多人0060就是用户指定的`20261012_095918_drinking_water_0060.mp4`。三段多人切片暂按用户所述全other查看：180次逐人判断中179次其他、1次喝水。0054的误报是T13在1.967秒，融合喝水分数0.75122。检测候选包括误检，16不能直接当作真实人数。

**当前效果不能直接替换生产。** 双人挥手3的前景未挥手者被持续判成喝水；挥手4也有类似问题。挥手20只出现1次挥手输出，其余为其他。可见每人独立输出已经实现，但把整帧pn2权重直接应用到人物ROI，输入尺度、形状填边和上下文均变了，动作能力没有自动得到保证。这些错误原样保留，没有修改模型输出来适配演示。

YOLO仍会把人形展品、背景形状等误判为人体（挥手3有短暂第三个候选），RTMO也存在漏检与误检。短期关联不能保证拥挤交叉和长遮挡后仍为同一人，测试只核验记录和实现配对，不是带身份真值的跟踪评估。握手、打架、追逐等动作依赖交互上下文，裁剪单人后尤其需要针对性训练与验证。

下一步若采用该方案，应按同一检测/跟踪/裁剪规则制作逐人训练数据，对RGB头微调并按人员/会话留出评估，再校准逐人融合与阈值；本轮未训练。旧全画面ABCP指标不可沿用为本方案成绩，旧线上P负样本也属于模型曾见过的数据。

## 运行与输入口径

四段现场原视频实际做Retinexformer增强。三段线上录像已经增强，裁掉76像素旧底栏后直接回放，不重复增强、超分或去噪；原始照度无法还原，双分支按原图不可用处理。最终现场样例1440×808、线上样例1680×944，均没有全局标签条，保持输入帧率和帧数。源码只在演示目录新增，生产源码、模型、算子包和镜像没有改动。

原0.3.0镜像缺少短期匹配使用的scipy，因此本轮在已有`.venv`原生环境运行，没有安装新依赖或修改镜像；这不是新平台包的容器兼容性验收。

本次离线演示：现场样例约10.2～10.8处理fps，16候选多人样例约4.6～5.5处理fps，包含该脚本的解码、推理、绘制、编码，模型加载不计入。不是实时服务或平台资源配置的对照测速，但**这版演示没有达到15fps**。相较旧整帧RGB只推理一次，逐人RGB成本随人数明显增加；尽管姿态已按帧复用、RGB采用批推理，后续仍须优化并实测端到端时延。

- 标签调整后已重新生成7段视频及封面，233条预测除新增阈值字段外与调整前完全一致，逐帧跟踪记录也完全一致。
